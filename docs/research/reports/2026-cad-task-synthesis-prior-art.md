# Set cover already solves the clue chain

**Status:** synthesis note, 2026-11-19. External literature analysis, not our result. Locates
the clue-chain construction engine in the classical set-cover and test-cover literature and
states what is genuinely new in CAD-QA's packaging. Exempt from the project glossary: it uses
the mathematical vocabulary of the fields it cites.

The construction engine in `03b` is not new mathematics. A chain of clues that narrows a finite candidate-answer set to a single answer is **literally the set-cover problem**, and in its all-pairs form it is the **minimum test collection** problem that Garey and Johnson catalogued as NP-complete in 1979; the "every clue strictly shrinks the set" rule is the standard **irredundant-cover** condition, provable as an equivalence rather than an analogy. The optimisation therefore has at least six published names across six literatures that do not cite each other — test cover, minimum test collection, minimal discriminant description, minimal complex, teaching dimension, and preset distinguishing sequence — and a reviewer from combinatorial testing or psychometrics will recognise the engine on sight. What is genuinely new is much narrower and quite specific: **no located system labels each step of a multi-step chain with a derivation-depth stratum**, uses the penultimate surviving set as its distractor pool, stops on tolerance-based answer equivalence rather than entity identity, or treats an *ordered* stratum profile as a coverage dimension backed by deficit accounting. The closest CAD precedent, BenchCAD, controls difficulty with a hand-assigned capability tier (L1–L4) rather than chain length ([arXiv:2605.10865](https://arxiv.org/html/2605.10865)); the closest controlled-depth precedents — CLUTRR, ProofWriter, MuSiQue, StepGame — control hop count but treat every hop as equally hard ([CLUTRR](https://aclanthology.org/D19-1458.pdf), [ProofWriter](https://arxiv.org/abs/2012.13048)). The consequence for the design document is that it should **name the classical optimisation and claim novelty only for the packaging**, because the packaging is where the defensible claims actually are.

## The engine is a set cover, and it has been named six times

The formal restatement is exact enough to be a reduction. Let `U` be the possible-answer set, let clue `i` have selection set `A_i = {u ∈ U : P_i(u) = true}`, and let the target `t` satisfy every clue. Applying a clue is set intersection, so the chain is the conjunctive concept `A_1 ∧ … ∧ A_n` restricted to `U`, and the final set is its extension. That object is a **complex** in Michalski's AQ framework and a **minimal discriminant description** when the extension is `{t}` — "a conjunction of attribute tests true of the target and false of all negatives" ([Michalski, *A Theory and Methodology of Inductive Learning*](https://www.mli.gmu.edu/papers/91-95/90-11.pdf)); the rough-set rule-induction literature calls the same thing a **minimal complex** ([Grzymala-Busse, *A New Version of the Rule Induction System LERS*, Fundamenta Informaticae 31, 1997](https://journals.sagepub.com/doi/pdf/10.3233/FI-1997-3113)). Because the target satisfies every clue, "find a cover" reduces to set cover over the distractor universe: each fact `f` contributes the set of distractors it falsifies. Set cover is NP-hard, greedy achieves `H_n = ln n + O(1)`, and `(1-ε) ln n` is inapproximable unless NP ⊆ DTIME(n^{O(log log n)}) ([Feige 1998, via the standard set-cover summary](https://en.wikipedia.org/wiki/Set_cover_problem)).

The all-pairs version — if a chain ever had to work for every target simultaneously — is the **minimum test cover** problem: a subfamily of tests such that every pair of items is separated by some test, "known to be NP-hard" with an `O(log m)` greedy ratio ([De Bontridder, Halldórsson, Halperin, Shachnai, Telle, *Approximation algorithms for the test cover problem*, Math. Programming 95(3), 2003](https://link.springer.com/article/10.1007/s10107-003-0414-6)), and no PTAS unless P=NP ([Halldórsson, Halperin et al., *On the approximability of the minimum test collection problem*, ESA 2001](https://link.springer.com/doi/10.1007/3-540-44676-1_13)). The applied version of exactly this problem shape — place sensors so every single fault is uniquely localised, then solve as minimum test cover — exists in water-network fault diagnosis ([Sela Perelman, Abbas, Koutsoukos, Amin, arXiv:1507.07134](https://arxiv.org/html/1507.07134v3)).

The third name matters most for the design's *process* claim. A fixed sequence of tests that uniquely identifies a state is a **preset distinguishing sequence** in FSM testing, and the field distinguishes preset from adaptive sequences explicitly ([Lee & Yannakakis, *Principles and methods of testing finite state machines — a survey*, Proc. IEEE 84(8):1090–1123, 1996](https://ieeexplore.ieee.org/document/533956/)); the single-state version is a **unique input/output (UIO) sequence**, "an input/output behavior that is not exhibited by any other state" ([Sabnani & Dahbura, *A protocol test generation procedure*, Computer Networks and ISDN Systems 15(4), 1988](https://www.sciencedirect.com/science/article/pii/0169755288900645)). Minimising these objects is hard in the same way: checking the existence of a characterising set of a given size is NP-hard ([Türker, *Minimizing characterizing sets*, 2021](https://www.sciencedirect.com/science/article/pii/S0167642321000381)).

Two equivalences are worth stating in the design document because they convert the design's "constraints" into cited theorems. First, **strict shrinkage is irredundance**: if `S_{i-1} ⊆ A_i` then dropping `A_i` leaves the final intersection unchanged, and conversely, so "every clue strictly narrows" holds exactly when the chosen test family is an inclusion-minimal cover. Second, **the chain is a filter pipeline, not a tree**: intersection is commutative, so the final set does not depend on clue order and no clue is skipped on a false branch. That is the preset regime, not the adaptive one.

## Four pieces survive the search as unclaimed

The notes converge on the same partition: the optimisation is textbook, the object is not. Four specific pieces appear genuinely unclaimed, and the confidence differs by piece.

**The derivation-depth ladder used as a generation lever is the strongest claim** (confidence: high that no precedent exists). The design does not merely *classify* a clue as S0–S5; it *re-expresses the same graph fact at a higher stratum by changing the operand binding* — "adjacent to the face created by `cutBlind`" (S2) becomes "adjacent to the face selected in step 1" (S3) becomes "adjacent to the face whose area is largest among the faces created by `cutBlind`" (S4). No counterpart was located in test-cover theory, cost-sensitive diagnosis, LLTM, or multi-hop QA generation. The nearest weak analogues are test *cost* in cost-sensitive diagnosis — a scalar price, not a depth — and hop count in multi-hop QA, which is a stratification axis but not a generation mechanism ([Lomax & Vadera, *A survey of cost-sensitive decision tree induction algorithms*, ACM Computing Surveys, 2013](https://dl.acm.org/doi/abs/10.1145/2431211.2431215)).

**Per-step derivation-depth labelling has no precedent at all** (confidence: high; see the dedicated section below).

**Tolerance-based answer-uniqueness as a stopping rule is unclaimed** (confidence: medium). Identification up to an equivalence class is studied as *equivalence class determination* in adaptive submodular maximisation ([Golovin & Krause, JAIR 42:427–486, 2011](https://www.semanticscholar.org/paper/Adaptive-Submodularity%3A-A-New-Approach-to-Active-Golovin-Krause/87887d5f5c61a610cbe2312c2a6f99439d96da82)), and with noise in [Golovin, Krause, Ray, NIPS 2010](https://cs.cmu.edu/~dgolovin/papers/nips10.pdf), but the equivalence relation there is "hypotheses the tests cannot distinguish", not "hypotheses that yield the same numeric answer within tolerance". The design's relation is **answer-induced**, and no covering-problem paper was found that uses it. Confidence is medium rather than high only because the CAD-grading literature is thin enough that an unindexed workshop paper could hide the idea: the entire tolerance record in CAD-QA is BenchCAD's **±5% on ratios** ([arXiv:2605.10865v2](https://arxiv.org/html/2605.10865v2)) and QueryCAD's regex/list equality, which is not a tolerance at all ([arXiv:2409.08704](https://arxiv.org/html/2409.08704)).

**The penultimate surviving set as distractor pool is unclaimed** (confidence: medium-high). MCQ-generation work selects distractors by similarity or taxonomic relation to the key — the closest published rule is Alsubait et al.'s `subs(C, L, O) = {D ∈ L | O ⊨ C ⊑ D}`, concepts related to the key by subsumption, with difficulty controlled by distractor–key similarity ([KI 2015](https://link.springer.com/article/10.1007/s13218-015-0405-9)). That is a *static* sibling relation, not a surviving-set relation. The design's rule carries a guarantee no distractor paper states: every distractor is provably consistent with all but the final clue, so the item cannot be answered without the last step.

**Ordered stratum profiles as a coverage dimension and deficit accounting for infeasible cells are both unclaimed** (confidence: high for the profile; high for the deficit in assessment, medium overall). A quota grid over feature combinations is well established, but in three traditions that each stop short: combinatorial testing has the sharpest formalism — variable-strength covering arrays, restricted arrays for infeasible factor combinations, and measurable coverage on arbitrary suites ([NIST IR 7878, *Combinatorial Coverage Measurement*, 2012](https://nvlpubs.nist.gov/nistpubs/ir/2012/NIST.IR.7878.pdf)) — but covering arrays cover *unordered* t-way tuples, and a sequence-valued dimension such as `[S2, S2, S4]` is outside that formalism. Assessment supplies the blueprint or table of specifications with per-cell counts ([Fives & DiDonato-Barnes, ERIC EJ1005136](https://files.eric.ed.gov/fulltext/EJ1005136.pdf)), but no assessment source reports unfillable blueprint cells as an output artefact; an infeasible assembly LP simply returns no solution. The nearest mature precedent for the ledger is hardware functional verification, where every unhit coverage bin must be classified **hit, unreachable, or excluded with justification**, often with a formal proof ([DenseChip, *Holes and Unreachable Bins*](https://densechip.com/topics/verification-first-principles/coverage/holes-and-unreachable-bins)).

The composite-object finding deserves one sentence of precision, because it is the one that could be overstated. It is **not** that the literature is ignorant of ordered narrowing chains — quiz-bowl pyramidal tossups are exactly that artefact, ordered hardest-first with the property that the number of players able to answer increases with each clue ([Rodriguez et al., arXiv:1904.04792](https://ar5iv.labs.arxiv.org/html/1904.04792)), and GuessWhat?! is the same object as a yes/no dialogue over an object set ([de Vries et al., CVPR 2017](https://arxiv.org/abs/1611.08481)). It is that in both cases the clues are untyped text and the narrowing is judged by a human or oracle, so neither can *certify* that a clue strictly shrank the set. The design's contribution to that lineage is machine-checkability, not the artefact.

## Every close precedent stops one step short

**In CAD**, a handful of distinct artefacts exist and none builds a chain. BenchCAD ships 2,400 questions (4,800 with both modalities) over 17,900 execution-verified CadQuery programs, with gold answers produced by **deterministic substitution of verified parameters** rather than by measuring the solid, and difficulty organised as a four-level capability hierarchy L1–L4 that is a property of the question, not of any chain ([arXiv:2605.10865](https://arxiv.org/html/2605.10865)). QueryCAD is 111 handcrafted questions over 18 STEP models with answers measured by a CAD kernel, and its authors state that no CAD-QA dataset existed before it and that GPT-4o-generated questions were "often unclear and ambiguous" ([arXiv:2409.08704](https://arxiv.org/html/2409.08704)). SGP-Bench poses 4-option multiple-choice questions about symbolic CAD command sequences, but they are semantic — colour, count, shape — not measurable BRep properties ([arXiv:2408.08313](https://arxiv.org/html/2408.08313v3)). BrepLLM/Brep2Text is the only large B-rep-plus-language benchmark, 269,444 QA over 134,722 models, but its answers are free-form descriptions graded by a Qwen3-30B judge and its two tiers are "abstract" and "beginner" ([arXiv:2512.16413](https://arxiv.org/html/2512.16413v2)). The BRep adjacency graph, per-face operation provenance, and before/after solid pairs are all standard — UV-Net and BRepNet use the graph as an encoder input, and the Fusion 360 Gallery annotates "over 35,000 B-rep models with information about the modeling operations which created each face" ([BRepNet, CVPR 2021](https://arxiv.org/abs/2104.00706)) — but the graph is never a question source. QueryCAD comes closest, using adjacency to prune faces during segmentation inside the *answering* system, not the generator.

**In controlled-depth generation**, hop count is the default axis of every synthetic multi-hop family. CLUTRR generates kinship stories and evaluates by relationship-chain length at depths 2–10, reporting that "the performance of all models degrades monotonically as we increase the length of the test clauses" ([Sinha et al., EMNLP 2019](https://aclanthology.org/D19-1458.pdf)). ProofWriter generates rulebases with proof depths D0–D5 and labels answers True/False/**Unknown** under open- versus closed-world assumptions ([arXiv:2012.13048](https://arxiv.org/abs/2012.13048)). StepGame makes the edge count between two entities the generator's knob and the reporting axis ([AAAI 2022](https://arxiv.org/abs/2204.08292)). MuSiQue is the closest of the four to the design's *validity* condition: it composes single-hop questions bottom-up and keeps only pairs that are "connected", meaning one reasoning step critically relies on information from the other ([Trivedi et al., TACL 2022](https://aclanthology.org/2022.tacl-1.31.pdf)) — structurally the same requirement as "no clue may be redundant", applied as a post-hoc filter rather than maintained as a search invariant. None of them has a candidate set to narrow, and all of them assume a k-hop item is homogeneous in per-step difficulty.

**In multi-axis difficulty**, two systems come close to the design's grid. CogniLoad is a synthetic logic-puzzle benchmark with **three independently tunable axes** — intrinsic difficulty `d` (interacting entities, attributes, clauses), distractor-to-signal ratio `ρ`, and task length `N` — motivated explicitly by the observation that existing benchmarks "typically manipulate only one dimension without systematic, independent control over the others" ([ICLR 2026](https://proceedings.iclr.cc/paper_files/paper/2026/file/10b7e27c8eb9571fbbd2ae6a9f8c3855-Paper-Conference.pdf)). GRADE models difficulty on "two orthogonal dimensions: (1) reasoning depth, defined by the number of inference steps (hops), and (2) semantic distance between the query and its supporting evidence", and criticises prior work for defining hops "merely in terms of the number of retrieved evidence chunks, rather than the logical compositionality of the reasoning required" ([Findings EMNLP 2025](https://aclanthology.org/2025.findings-emnlp.236.pdf)). Both report **marginals** across their axes rather than per-cell estimates, and neither publishes a minimum-items-per-cell rule.

**In derivation-depth weighting**, the formal template is the Linear Logistic Test Model, which decomposes the Rasch item parameter into a weighted sum of hypothesised cognitive operations with a Q-matrix as the item × operation incidence matrix ([Fischer, *Acta Psychologica*, 1973](https://www.sciencedirect.com/science/article/pii/0001691873900036); [Baghaei & Hohensinn, Frontiers in Psychology, 2017](https://www.frontiersin.org/journals/psychology/articles/10.3389/fpsyg.2017.00897/full)). The cognitive design system around it supplies the vocabulary the design needs — *radicals* that should move difficulty versus *incidentals* that should not — and reports that in an automatically generated number-series item bank "all stimulus features implemented in the automatic item generator proved to be significant predictors of item difficulty, explaining 77% of the total variance" ([Sun, Liu & Luo, Frontiers in Psychology 10:884, 2019](https://www.frontiersin.org/journals/psychology/articles/10.3389/fpsyg.2019.00884/full)). One result here is a direct warning: an expert-defined Q-matrix reached R² = 0.528 against Rasch parameters while an LLM-assisted one reached R² = 0.815 ([Gorbacheva et al., *Practical Assessment, Research & Evaluation* 31(1)](https://publications.hse.ru/pubs/share/direct/1205345166.pdf)) — hand-assigned structural annotation can explain far less variance than an automatically derived one.

**In global selection**, automated test assembly is the mature formal analogue: 0-1 linear programming over a fixed item pool under blueprint counts, exposure caps and enemy-item constraints ([van der Linden, *Linear Models for Optimal Test Design*, Springer 2005](https://link.springer.com/book/10.1007/978-0-387-85461-8)), with the shadow-test variant re-solving the whole constraint model at each local decision ([van der Linden & Reese 1998, recorded in *Computerized Adaptive Testing: Theory and Practice*](https://link.springer.com/book/10.1007/0-306-47531-6)). The architectural resemblance to "local synthesizer consults a global plan" is real; the difference is economic. ATA is a **selection** model — binary include/exclude over items that already exist — whereas the quota scheduler is a **procurement** model, where no pool exists until candidates are produced, so the constraint set is over cells rather than over items. That is closer to a multi-unit procurement or assortment problem than to ATA, and no source was found that formulates dataset construction as scheduling over *to-be-generated* items.

**In the algorithmic core**, three objects bracket the design. Test cover supplies the optimisation and its approximation bound. Teaching dimension supplies the closest *quantity*: `td(C) = max_c min_T |T|`, the minimum number of examples a teacher must reveal to uniquely identify any concept in the class ([Goldman & Kearns, *On the Complexity of Teaching*, JCSS 50(1):20–31, 1995](https://www.cis.upenn.edu/~mkearns/papers/teaching.pdf)) — the design computes the *inner* term, a minimum teaching set for one target, not the max over concepts, and it uses only positive information, which is why the optimisation collapses to set cover rather than to the harder two-sided teaching problem. UIO and distinguishing sequences supply the *process*: a fixed test sequence that identifies one state, decided in advance, with no branching. Both stop exactly where the design continues — test cover at the unordered family, teaching dimension at the single concept, UIO at the single state with no answer step and no derivation-depth label.

## Derivation depth is the axis nobody labels per step

This is the design's most distinctive claim and the one with the cleanest negative finding: **no located work assigns a derivation-depth stratum to each step of a multi-step reasoning chain and uses it as a benchmark axis**. Every existing controlled-depth benchmark labels the *item*, not the step — CLUTRR and StepGame by hop count, MetaQA by directory (1-hop, 2-hop, 3-hop), ProofWriter by proof depth, BetaE and Query2Box by query structure ([BetaE](https://snap.stanford.edu/betae/)), KQA Pro and GrailQA by program structure ([KQA Pro, ACL 2022](https://aclanthology.org/2022.acl-long.422/), [GrailQA](https://huggingface.co/papers/2011.07743)). The design's claim that four S0 clues are not the same item as two S4 clues is, on this search, an unoccupied axis.

The five near-analogues each cover part of it, and the differences are instructive. **LLTM is the formal template**: stratum as a weighted sum of derivation operations is exactly LLTM's difficulty = Σ(operation cost × Q-matrix weight), and S0–S5 is a coarse LLTM with unit weights. What LLTM does not do is apply the decomposition per step within a chain; it predicts one number per item. **SOLO is closest in content**: its five levels are "identified by analyzing the components and structure of the response… based on the amount of working memory used, relevant operations, consistency, and closure", and its "relational" level is essentially "the operand is a prior result" — the same intuition as S3 ([SOLO systematic review, EJMSTE](https://www.ejmste.com/article/structure-of-the-observed-learning-outcomes-solo-model-a-mixed-method-systematic-review-of-research-12087)). But SOLO grades a learner's *response*, human-assigned, not a typed expression. **Van Hiele is the validated prerequisite hierarchy**: five levels, "sequential and hierarchical", with the claim that "a pupil cannot be at level n without having passed through level n−1" statistically confirmed by Guttman analysis in several studies ([Revisiting the Van Hiele Theory](http://dynamicmathematicslearning.com/revisiting-van-hiele-EIEM-Portugal2017.pdf)). That is a learning hierarchy, not an item-difficulty scale — and it is the methodological precedent for testing whether S0–S5 is actually a scale. **Bloom is explicitly not a difficulty scale**: the taxonomy "aims to rank the complexity of a task, measuring depth of mastery, and as such does not correlate exactly with difficulty" ([Dunham, *J. Statistics Education* 23(3), 2015](https://jse.amstat.org/v23n3/dunham.pdf)), and a medical progress-test study found "a 54% match between the panel of experts' expectations and the real difficulty of items" ([PMC9673841](https://pmc.ncbi.nlm.nih.gov/articles/PMC9673841)). Citing Bloom as a difficulty ladder is the standard error this literature warns against.

The two sharpest analogues sit outside education. **Cognitive Complexity** (Campbell, SonarSource) is a code metric built on exactly the design's motivating observation — that cyclomatic complexity "measures the number of execution paths without accounting for how hard they are to follow", so two methods with equal counts can be "strikingly different in terms of understandability" — and it implements it as *structural increment per control-flow break plus an extra penalty per nesting level* ([SonarSource whitepaper](https://www.sonarsource.com/docs/CognitiveComplexity.pdf)), which is the closest formal shape to "one step per derivation, plus a higher stratum when the operand is itself derived". It correlates with the time developers take to understand code ([MDPI Computers 13(3), 2024](https://www.mdpi.com/2073-431X/13/3/75)), but it is a metric over programs, not a difficulty axis for items. **Logic-grid puzzle generation** is the nearest in spirit to per-step operation grading: puzzle difficulty "is often determined by an automatic solver either through total processing time or by the types of moves solvers make", and FI-2Pop genetic search produces solvable, diverse, difficult puzzles on that basis ([Shyne, Facey, Cooper, FDG 2024](https://dl.acm.org/doi/pdf/10.1145/3638530.3654337)). That grades a chain by the operations a solver must perform — but the operations are derived from a solver trace, not computed from a typed clue, and there is no answer step.

The A0–A3 answer ladder has no precedent at all. It resembles a measurement-scale ladder more than a derivation ladder, mixing answer *type* (identity, measurement, derived measurement, effect) with derivation depth, and no source was located for it. That is an absence to state plainly rather than defend.

## Step count is monotone inside a generator and nowhere else

The design proposes two axes: step count and clue stratum. The literature supports a two-part claim about the first, and only the first part helps.

**Within a single generator, step count is reliably monotone.** CLUTRR degrades monotonically with chain length for models, and its human annotators score above 70% at k ≤ 3 and 40–50% beyond ([EMNLP 2019](https://aclanthology.org/D19-1458.pdf)). The Long Reasoning Benchmark reports that "accuracy decreases as the expected number of reasoning steps increases, following a strong linear trend with respect to the logarithm of steps", with R² > 0.96 for GPT-5 and Claude Opus 4.5 ([Findings EMNLP 2026](https://aclanthology.org/2026.findings-emnlp.120.pdf)). GSM-Symbolic finds that "performance significantly deteriorates as the number of clauses in a question increases" ([Mirzadeh et al., ICLR 2025](https://proceedings.iclr.cc/paper_files/paper/2025/file/ec2e7a896f8250986b3907f57621ce94-Paper-Conference.pdf)). This is the defensible version of the design's step-count claim: inside one generator with everything else held fixed, length works.

**Across datasets and against human judgement, it does not transfer.** The strongest negative result is an IRT analysis finding that "most datasets show very little to no positive correlation between IRT difficulty scores and human-based metrics", where the human metrics examined include "the number of reasoning steps for math datasets (GSM8K & MATH)", and concluding that "difficulty is not a universally agreed-upon metric; it is inherently relative, subjective, and language model-dependent" ([*Revisiting Generalization Across Difficulty Levels: It's Not So Easy*, EACL 2026](https://aclanthology.org/2026.eacl-long.330.pdf)). The same paper characterises step count as a *heuristic*, not a measurement. And monotonicity is architecture-conditional even inside one generator: on ReaSCAN's clause-count ladder, M-LSTM drops 93.39 → 60.68 → 53.08 from Simple to 2-relative-clauses while GCN-LSTM drops 98.06 → 97.25 → 96.80, a 43.65% relative drop versus 1.03% ([Wu et al., NeurIPS 2021 D&B](https://datasets-benchmarks-proceedings.neurips.cc/paper/2021/file/2838023a778dfaecdc212708f721b788-Paper-round1.pdf)).

The implication for a `(step_count, max_clue_stratum)` reporting grid is that the first axis is defensible as a within-generator design parameter and the second is unvalidated as a difficulty measure — it is a *description* of the item, not a prediction of difficulty. That distinction is already present in the design as D9 ("equal first, then calibrate against LLM model results"), which in psychometric vocabulary is precisely the LLTM programme: move from an assumed equal-weight structural scale to an empirically calibrated one. Worth noting alongside it: IRT supplies two things a structural grid cannot — an empirical difficulty `b` on a common scale and a discrimination `a` that says whether an item separates strong from weak models at all — and a cell can be perfectly populated with zero-discrimination items. IRT also cannot be used at generation time, needs response data, and is unstable when the model count is small relative to item count ([*Can We Trust Item Response Theory for AI Evaluation?*, arXiv:2607.15190](https://arxiv.org/html/2607.15190v3)). The two are complementary, and the design's plan to calibrate later is the correct shape for the evidence available.

## Five premises in the design need correcting

**Greedy does not give the shortest chain.** The design states "a greedy cover gives the shortest chain; a less greedy cover gives a longer chain". Greedy set cover achieves `H_n = ln n + O(1)`, and no polynomial algorithm achieves `(1-ε) ln n` unless NP ⊆ DTIME(n^{O(log log n)}) ([Feige 1998](https://en.wikipedia.org/wiki/Set_cover_problem)); for the test-cover special case the greedy ratio is `O(log m)` ([De Bontridder et al. 2003](https://link.springer.com/article/10.1007/s10107-003-0414-6)). Greedy is a log-factor *approximation*, and the natural information-gain heuristic is provably not optimal even for binary identification ([Garey, *Simple Binary Identification Problems*, IEEE Trans. Computers, 1972](https://ieeexplore.ieee.org/document/5009013/); [Hyafil & Rivest, *Constructing optimal binary decision trees is NP-complete*, IPL 5(1), 1976](https://www.sciencedirect.com/science/article/pii/0020019076900958)). The design's *use* of greedy survives — it is a search parameter, and non-greedy choices genuinely produce larger irredundant covers — but the word "shortest" is wrong and a reviewer will catch it.

**The chain is not a decision tree.** The design's section heading "a decision tree over possible answers" is a misnomer that propagates. Intersection is commutative, so the final set is order-independent and no clue is ever skipped or replaced on a false outcome; the "tree" has one non-empty child at every node. That makes the decision-tree literature the wrong comparison and, more sharply, makes **metric dimension and identifying codes the wrong frame** — those restrict tests to neighbourhoods or distance vectors and demand separation of *every* pair, while the design separates one element from the rest with arbitrary predicates. The right comparisons are **preset test sequencing** and **set cover**. This also changes which hardness result applies: Chakaravarthy et al.'s `Ω(log N)` inapproximability is for the *adaptive* entity-identification tree ([PODS 2007](https://dl.acm.org/doi/10.1145/1265530.1265538), [ACM TODS 2011](https://dl.acm.org/doi/10.1145/1921659.1921661)); the non-adaptive case is set cover, with the tighter `ln n` bound. The only order-sensitive content is the binding structure (S3/S4 referring to "the face selected in step 1"), which makes the object closer to a query plan — a pipeline of selections — than to a tree.

**The Hugging Face artefact is this project's own.** `MRiabov/cadqa-rl-2000` looks exactly like the missing prior art: rows "derived from the CAD-QA benchmark (`release_10k` train split, `cad_browsecomp` difficulty)", generated "by the CAD-QA pipeline (AST/dataflow graph + CadQuery execution) from the public CADEvolve source corpus", with fields `logical_hop_count`, `geometry_hop_count`, and `relation_families`, and prompts of the form "Identify the target path point that satisfies all of these constraints… Within the narrowed set, select the candidate with the maximum Y coordinate" ([HF dataset card](https://huggingface.co/datasets/MRiabov/cadqa-rl-2000)). It must **not** be cited as external prior art; it is this project's output, and citing it would be a self-citation dressed as a precedent.

**Petty et al. is model depth, not task depth.** "The Impact of Depth on Compositional Generalization in Transformer Language Models" ([NAACL 2024](https://aclanthology.org/2024.naacl-main.402.pdf)) is about transformer layer count. The title is a trap and it will be mis-cited if it appears in a related-work list about task depth.

**Four citations in the algorithmic notes are secondary-sourced or unverified, and two more are second-hand.** Feige 1998 is recorded "via the standard set-cover summary" rather than the primary paper; Reiter 1987 (*A theory of diagnosis from first principles*, AI 32) is explicitly flagged as not fetched; the general-case NP-hardness of computing teaching dimension is unverified, with only the recursive variant confirmed ([Manurangsi, IPL 2024](https://www.sciencedirect.com/science/article/abs/pii/S0020019023000728)); and Kautz & Singleton 1964 is quoted "as cited in this survey". Katona 1966 / Rényi 1961 and Rivest, Meyer, Winklmann & Werman 1980 are likewise second-hand but uncontroversial. Verify all six against primary sources before submission. A related trap: the design's "witness set" (survivors that agree on the answer) is a *different* use of the phrase from the teaching literature's "witness set", which means teaching set — pick one and disambiguate it in the text. Finally, several 2026 citations in these notes carry title, venue and URL but no author list; fill those in from the PDFs rather than from memory.

## What to cite, and why

- **De Bontridder, Halldórsson, Halperin, Shachnai & Telle (2003), *Approximation algorithms for the test cover problem*, Math. Programming 95(3)** — names the optimisation and gives the `O(log m)` greedy ratio for the all-pairs form.
- **Feige (1998), *A threshold of ln n for approximating set cover*, JACM 45(4)** — bounds what greedy can promise; the citation that corrects "greedy gives the shortest chain".
- **Michalski (1983), *A Theory and Methodology of Inductive Learning*** — the single-target form: minimal discriminant description as a conjunction true of the target and false of all negatives.
- **Lee & Yannakakis (1996), *Principles and methods of testing finite state machines — a survey*, Proc. IEEE 84(8)** — the preset-versus-adaptive distinction, which is the correct framing for a non-branching chain.
- **Ünlüyurt (2004), *Sequential testing of complex systems: a review*, Discrete Applied Mathematics 142** — ordered tests with precedence and cost, the closest match to dependency-ordered clues.
- **Golovin & Krause (2011), *Adaptive Submodularity*, JAIR 42** — equivalence-class determination, the nearest published notion to answer-uniqueness.
- **Fischer (1973), *Acta Psychologica*** — LLTM, the formal template for stratum as a weighted sum of derivation operations.
- **Biggs & Collis (1982), *Evaluating the Quality of Learning: The SOLO Taxonomy*** — the closest ladder in content, grading by operation count and working-memory demand.
- **ProofWriter (2020), arXiv:2012.13048** — depth-controlled generation with a three-valued True/False/Unknown label set.
- **CLUTRR (Sinha et al., EMNLP 2019)** — depth-stratified generation with demonstrated monotonicity in chain length.
- **MuSiQue (Trivedi et al., TACL 2022)** — the "connected reasoning" filter, the nearest published analogue of strict shrinkage.
- **CogniLoad (ICLR 2026)** — independent multi-axis difficulty control, the closest existing grid.
- **BenchCAD (arXiv:2605.10865)** — the closest CAD-QA artefact, and the evidence that CAD difficulty is a capability tier rather than a chain length.
- **van der Linden (2005), *Linear Models for Optimal Test Design*, Springer** — automated test assembly and shadow tests, the global-selection lineage.
- **Kuhn, Kacker & Lei (2021), *Factorials Experiments, Covering Arrays, and Combinatorial Testing*, NIST** — variable-strength and restricted covering arrays, the formal home of the quota grid.

## Conclusion

The literature's silence is not ignorance; it is a boundary between fields. Combinatorial optimisation stopped at the unordered cover and never asked what a clue costs to *evaluate*. Psychometrics stopped at the per-item operation count and never asked what a step costs inside a chain. NLP stopped at hop count and never asked whether two hops of the same length are equally hard. The design sits precisely at the intersection of those three stopping points, which is why no single paper subsumes it and why the novelty claim has to be stated as a **composition claim** rather than an invention claim.

The strongest defensible piece is not the ladder itself but the **generation lever** — re-expressing one graph fact at a higher stratum by rebinding its operand. That is the one element that is neither a renaming of something classical nor a small variant of something adjacent, and it is the element a reviewer is least likely to have seen. The weakest is the A0–A3 answer ladder, which has no precedent and should be presented as a design choice rather than as a derived scale. Everything in between should be cited by its classical name and claimed only for how it is combined.
